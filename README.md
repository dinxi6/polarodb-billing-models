## 先搞清楚：PolarDB的钱花在哪几块

PolarDB采用计算与存储分离架构，计费方式直接跟着架构走：计算和存储分开收钱。具体是这么构成的：

- **计算节点**：按规格（核数、内存）收费，计费方式三选一——按量付费、包年包月、Serverless
- **存储**：按实际用量按量计费，不用提前买容量，存了多少数据就付多少
- **数据库代理**：免费，自动读写分离、负载均衡、连接池、过载保护都包含在内
- **冷数据归档**：不常访问的数据可以归档到OSS，存储成本更低

共享存储还有一个容易被漏掉的好处：所有节点共用同一份数据，增加只读节点只需要付节点的计算费用，存储不会随节点数翻倍。传统主备架构每加一个节点就要多存一份数据，这笔开销在PolarDB上省掉了。

## 三种计费方式分别适合谁

### 按量付费：短期需求用这个

按实际运行时长计费，创建按量付费集群开始出账，用完释放，计费即停。适合短期测试、临时项目、跑压测这类“用几天就撤”的场景。它和包年包月的核心区别在于灵活性：不需要为未来的使用量做承诺。

### 包年包月：长期业务最划算

预付费模式，一次买的时间越长，折扣越大。业务如果确定要7×24小时长期运行，包年包月几乎总是比按量付费便宜。成长期的公司建议先按月或按季度买，规格稳定后再拉长周期。

## 存储费用：最容易漏算的部分

很多人对比价格时只看实例规格，结果账单出来发现多了一笔——那就是存储费。PolarDB的存储按实际用量按量计费，数据涨到多少就按多少收。好消息是它有三个降成本的机制：

1. **Smart-SSD**：在保证速度的前提下做高压缩比，官方数据是存储成本可以降低40%
2. **冷数据归档**：不常访问的数据归档到OSS，比留在高性能存储上便宜得多
3. **共享存储**：加只读节点不复制数据，扩容读能力的成本只有计算那一半

举个例子：如果你的业务读流量大，准备加两个只读节点，在PolarDB上你只需要付两个节点的计算费；在传统主备架构上，同样的操作还意味着两份完整的数据副本。
